Help & Guide
What this app does

The SimFly Reciprocation Tracker helps you keep track of which pilots have flown to your airports so you can prioritise flying back to theirs. It scores each pilot by how overdue a return visit is and how loyal a flyer they've been, then surfaces who to fly to next. Data is stored in a private GitHub Gist so it's available on any device.

🚀 Getting started
  1. On first load, enter your Reciprocation Gist ID and your GitHub Personal Access Token (PAT) with gist scope. Check Remember on this device to store them across sessions. The app loads your data from the Gist automatically.
  2. Once connected, the Balance Queue and Quick Entry panel appear.
  3. Open your SimFly PAX wallet log and start entering flights from where you last left off — the Last Entry timestamp tells you your cutoff.
  4. To disconnect or switch tokens, click Forget Token in the toolbar.
✈️ Logging flights (Quick Entry)

This is the fastest way to record a batch of inbound flights from your SimFly log.

  1. Type a pilot's name or 3-letter code into the Pilot field. A dropdown appears — use arrow keys or click to select.
  2. Press Enter (or click Log Flight ↵) to record one inbound flight for that pilot and reset for the next entry.
  3. The This session log below shows every entry with an Undo button for mistakes.
↓ Data import panels (Sync Inbound · Pilot Payout)

Both the ↓ Sync Inbound Flights from SimFly panel and the 💰 Pilot Payout Data panel share the same two-step workflow:

  1. Step 1 — Console snippet. While logged in to simfly.io, open DevTools (F12 → Console). Click ⎘ Copy snippet on the panel (or select the snippet textarea and copy manually), paste it into the console, and press Enter. A textarea appears on the SimFly page with the JSON output.
  2. Step 2 — Paste JSON output. Copy that JSON, paste it into the Step 2 textarea (or click ⎙ Paste to pull from clipboard), then click ↓ Import.

The Sync Inbound panel adds new flights to your log, skips duplicates, and auto-creates any pilots not yet in your roster (with a 3-letter code derived from their username). Every imported flight lands in the Session Log with two extras: the destination airport ICAO (shown as → KBOI after the pilot name) and, for the flight that first introduced a pilot, a green NEW pill. Both markers persist into saved session history.

The Pilot Payout Data panel updates the community payout-percentage map; after import, a diff modal shows every airport added, removed, or changed with the owning pilot's name and signed delta. The data is pushed to the shared Active Airports Gist so AA reflects it immediately, and the data feeds the 💸 Payouts leaderboard (toolbar button) — a sortable table that joins each pilot's payout % with your inbound/outbound flight counts so you can see at a glance who you owe a visit to and which visits would be most lucrative.

The payout import also captures each airport's owner and category. Airports whose owner RT didn't already know are added to the shared owner list, airports whose owner has changed are transferred to the new owner (same process the KML Generator uses), and newly-seen categories are written to the category list — so owner and category data stay current with no manual editing. These updates need a GitHub PAT connected; the diff modal's Owner & Category Sync section reports exactly what was written.

🆕 Adding a new pilot
  1. Type a name you haven't logged before into the Quick Entry pilot field and select + Add "[name]" as new pilot from the dropdown — the Add Pilot form appears inline. (Existing entry points like the Pilot Directory's Track → button still open the same form when promoting a known owner.)
  2. A form appears: the 3-letter code is auto-suggested from the username — edit if needed.
  3. Optionally fill in the first-airport ICAO and the pilot's SimFly profile URL right there — both fields skip the round-trip through Edit Pilot.
  4. Shortcut: in SimFly, highlight a pilot's name and click Copy Link (e.g. https://simfly.io/logbook/cromen157/1773276004), then paste it directly into the Pilot field. The username and URL are extracted automatically — if the pilot is new, the mini-form opens pre-filled; if already in your roster, they are selected and the URL is saved if they didn't have one.
  5. Press Enter to confirm. The pilot is created and the flight is logged immediately.
🔗 Pilot profile links

Pilot names in the main table, the SESSION LOG, and the analytics charts are clickable links to that pilot's SimFly profile page. Click the row to set departure/arrival as before — only the underlined name text triggers the profile link.

  • Cyan dotted underline — a profile URL is set. Click to open it in a new tab.
  • Amber dashed underline — no URL set yet. Click to paste one inline; it saves and opens immediately.
  • You can also set or change the URL anytime from ✎ Edit on a pilot's row — the field is labelled SimFly Profile URL.
✉️ Welcome Queue
  1. Every new pilot is automatically queued for a welcome message when they are added with a first airport ICAO.
  2. Click ✉ Welcome Queue in the toolbar — pending messages are sorted oldest-first.
  3. Click the pilot's name to copy just the name, or click the Subject line to copy the “Thank you for your flight to …” subject — both go straight to the clipboard for quick paste into SimFly's messaging dialog.
  4. Click Copy & Preview to open the message preview. Use ← Prev / Next → to browse all 10 variants.
  5. Click Copy to clipboard, paste into SimFly's messaging system, then click Mark as Sent ✓.
↩️ Logging a return flight

When you fly to a pilot's airport, click ↩ Recip in their row. This stamps a return flight and resets the reciprocation date to now — so the queue reflects only flights since your last visit.

If your route banner covers two SimFly-owned airports (e.g. you flew from one pilot's airport to another's), the modal shows a ROUTE — BOTH AIRPORTS ARE SIMFLY-OWNED panel listing each side's owner with a status pill: ✓ SELECTED (the pilot you clicked), ✓ ALSO CREDITED (the other route owner — both will receive a return-flight entry on submit), or not in your roster for airports whose community owner isn't tracked locally. When only one side is SimFly-owned the header reads SIMFLY-OWNED AIRPORT (singular).

🗺️ Plan Flight → Active Airports

Use the inline ✈ Dep and ✈ Arr buttons on any pilot row to set that pilot as your departure or arrival. Once both sides are set, a Route banner appears showing the distance and a ✈ Launch button. Clicking it opens the Active Airports app pre-loaded with your route, owner selections, and currently selected aircraft — ready to view the distance matrix and file on SimBrief.

The Active Airports URL defaults to the hosted web version at kyndrarocks.github.io/SimFlyActiveAirports — click the URL shown in the toolbar to override it if needed.

Once you have filed your route on SimBrief, click 📥 SimBrief (in the route banner or toolbar) to pull the departure and arrival airports back into the Tracker automatically. The Balance Queue updates immediately to highlight the correct owners. Your SimBrief username is saved on first use — shift-click the button to change it.

✈ Aircraft selector

The aircraft selector (top of the main panel) lets you choose which aircraft you're flying. This affects two things: the C700 Capable metric and airport badges (airports incompatible with the selected aircraft are flagged), and the aircraft data sent to Active Airports when launching Plan Flight. The Fuel and Payload sliders set departure load: lighter loads shrink the required runway, and the panel shows the resulting Req runway, MTOW, and achievable Range. Range uses the same physics-based calculation as Active Airports — published range scaled by your current fuel and payload — so it updates live as you drag the sliders.

🏢 Airport ICAOs & capability

Each pilot's airports are loaded automatically from the community Active Airports Gist at startup — no manual entry needed. The app checks OurAirports runway data to flag which airports are operable for the selected aircraft (category, runway length, surface). The Has airports filter in the Balance Queue hides pilots with no registered airports — reciprocation requires flying to one of their airports.

⚖ Balance Queue (main view)

The Balance Queue is the main screen of the app — a divergent bar chart showing every tracked pilot's inbound visits to you (right, cyan) vs your outbound returns to them (left, green). All pilots are shown — no cap.

  • Click a row to expand it — reveals the pilot's airport ICAOs (click any chip to set it as your dep/arr) plus ✈ DEP, ✈ ARR, ↩ Recip, and ✎ Edit buttons. Click the row again to collapse.
  • Sort headers — click Pilot, ← Outbound, or Inbound → (and the count columns beside them) to sort by that column. Click again to reverse direction. An arrow (▲/▼) shows the active sort and direction. Default: Inbound, highest first.
  • Search — type in the filter box to instantly narrow by pilot name, 3-letter code, or airport ICAO.
  • Date range slider — drag the slider to set how far back the queue looks. It snaps near the marked presets (3d · 7d · 14d · 30d · 90d · 1yr · All) or stops anywhere for a custom value like 5 days; click a tick label to jump straight to it. The chart updates live as you drag. Your chosen window is remembered, so the queue reopens on the same range next time.
  • Hide inactive — hides pilots with zero activity in both directions within the date range.
  • Has airports — hides pilots with no registered airports (can't be reciprocated to).
  • Last recip ≥ N days — shows only pilots you haven't flown to in at least N days (or never). Uses the all-time last-recip date regardless of the slider — good for surfacing the most overdue relationships.
  • Inbound ≥ N — shows only pilots who have visited you at least N times within the current date window.
  • Ratio ≥ X:1 — shows only pilots whose inbound-to-outbound ratio meets or exceeds X. Pilots with no outbound flights always qualify (their ratio is effectively infinite).
  • ▣ Select pilots → send to AA — click it to start picking pilots, tick any you want to focus on (e.g. those needing attention), then click 🗺 Send to AA → to open the Active Airports region map showing only those pilots' airports. Selection mode also shows a ▣ Select outbound tool — a number box plus button. Click the button to engage it (it turns green): every visible pilot with that many or fewer outbound flights is selected, and the selection tracks live as you move the date slider or change the number. Clicking an individual pilot row switches back to a manual selection. The 🗺 Send to AA count always reflects only the pilots currently visible — change a filter and it updates; pilots hidden by a filter are never sent. After you send, selection mode closes and each pilot in the batch keeps a ✓ Sent badge on its row for the rest of the session.
💰 Pilot Payout Data & History

The 💰 Pilot Payout Data panel (above the Aircraft selector) lets you capture, import, and push community payout percentages without opening KML Generator. Click 📋 Copy Snippet, run it in the SimFly console, paste the resulting JSON, and click ⬆ Import. A diff modal pops up showing exactly what changed since the last import — airports added, removed, and changed with signed deltas — and the new totals are pushed to the shared Active Airports Gist immediately. The same import also harvests each airport's owner and category and folds them into the shared owner list and category CSV — adding unknown airports, applying ownership transfers, and recording new categories automatically.

There are two ways to open the chart view: 📈 Payouts in the main toolbar (always accessible, no import required) or 📈 History on the Pilot Payout Data panel itself. Both open the same modal. The By Airport tab shows a step-line chart of one airport's payout % over time; pick any ICAO from the dropdown to switch. The By Pilot tab shows a faint line per airport that pilot owns plus a bold white average line across all of them — click an airport chip in the legend to jump to its detailed view. Every event in the underlying log is timestamped, attributed to the airport's owner at that moment, and synced via a separate file in the same AA Gist so history travels between machines.

📊 Recip Dashboard

Click 📊 Dashboard in the toolbar for a detailed history view. Pick a date range at the top (or a preset: All time / Last 12 months / 90 days / 30 days) — the entire page updates to that range. Sections:

  • Summary chips — at-a-glance totals: outbound returns, distinct pilots reciprocated, distinct destinations visited, and inbound visits / pilots visiting you / last visit received for context.
  • ↩ Top Pilots Visited — horizontal bar chart of the top 20 pilots you've reciprocated to, ordered by count.
  • 📍 Top Destinations — horizontal bar chart of the top 20 destination ICAOs you've flown to. The roster owner of each ICAO is shown alongside when known; ICAOs with no roster owner are flagged.
  • ↩ Reciprocation List — every return flight you've performed (newest first). Type in the Filter box to narrow the list by pilot name or airport ICAO as you type. Sort by date / pilot, click ⬇ CSV to export the visible list.
  • ⤓ Backfill from SimFly — collapsible at the bottom for seeding historical reciprocations from before v2.14.0. 💾 Saving & exporting
  • Auto-save writes to the Gist every 5 entries and every 2 minutes if there are unsaved changes. The unsaved count is shown in the toolbar.
  • Export downloads a dated JSON backup — keep these as manual snapshots.
  • Import restores from a backup file — use with care, data is merged not replaced.
  • Forget Token clears all stored credentials and returns to the PAT gate.

Paste the JSON the snippet copied. Each entry should look like {"ts":"2026-03-28T04:04:21+00:00","departureIcao":"PAFA","destinationIcao":"PACD"}. v2.63.0 Aug 15, 2026 · Current Improved
  • Flight history charts redrawn. The per-pilot chart behind an expanded Balance Queue row has been rebuilt to read like a real chart rather than a sketch. The plot now sits on its own defined surface with a hairline frame; the inbound and outbound fills fade out toward the baseline instead of sitting as flat blocks; lines are drawn a touch heavier with rounded joins; and every dot wears a thin ring in the surface colour so an inbound and an outbound flight on the same day stay two readable marks instead of merging into one blob.
  • Dots are round again. The chart used to be drawn small and then stretched sideways to fit the panel, which squashed every circular dot into an oval and thinned the lines unevenly — the single biggest reason the chart looked unfinished. It is now drawn at its true size, so circles are circles and stroke weights are even everywhere.
  • Hover anywhere on the chart. A vertical crosshair follows your pointer, snaps to the nearest day, and shows one readout giving that date with both the inbound and outbound counts — so a day with no flights answers "0 flights" rather than nothing at all. Previously you had to land the pointer precisely on a 4-pixel dot to get anything, and each dot only spoke for its own series.
  • Overlapping dates at the right edge fixed. The axis drew a label every six days and a pinned label at today, so when those fell a day or two apart the two dates printed on top of each other as an unreadable smudge. A tick that crowds the pinned one is now dropped.
  • Fewer gridlines behind busy charts. Horizontal gridlines were drawn at every single flight count, so an active pilot got twenty-odd lines competing with the data. They now appear only at the numbered steps, and light vertical guides drop from each date so you can carry a date down to the marks.
  • Web / Desktop toggle removed. The 🌐 Web / 🖥 Desktop switch beside the route launch button and the bulk Send to AA button has been removed, along with the setting behind it. It chose between opening a route in the hosted Active Airports and handing it to the Active Airports Desktop app, but that app was retired on August 1 — so one side of the toggle pointed at nothing. Routes always open in the hosted version now, which is what the toggle already defaulted to.
v2.62.0 Aug 15, 2026 Fix
  • Airport suitability now checks takeoff, not just landing. The Has airports suitable for <aircraft> filter — and the green/dim state of every ICAO chip — only ever asked whether the aircraft could land at an airport. Because the landing check assumes a near-empty aircraft (a 10% fuel reserve), that let through fields the aircraft could never depart from: a Citation X was counted as capable at a 1,617 ft strip on the strength of a 1,478 ft landing roll, while the REQ RUNWAY panel was simultaneously reporting that it needed 4,145 ft to get airborne at a 60% fuel load. An airport now counts as suitable only if a single runway satisfies both requirements, so a pilot no longer surfaces in the Balance Queue on the strength of a one-way field.
  • Takeoff density-altitude penalties added. Required distances are corrected for the airport's density altitude, but the correction table only ever held landing factors (3.5–4% per 1,000 ft), which badly understate the takeoff case. The full per-category table from Active Airports is now in place, with separate takeoff factors ranging from 7% per 1,000 ft for jets up to 12% for light piston singles. High-elevation airports will therefore look meaningfully less capable than before — correctly so.
  • ICAO tooltips show both numbers. Hovering an airport chip now reads “T/O needs 4,145 ft · LDG needs 1,478 ft” rather than the landing figure alone, and an unsuitable airport names the phase that actually fails — so “T/O needs 4,145 ft, longest 1,617 ft” instead of a landing figure that clears comfortably and explains nothing.
